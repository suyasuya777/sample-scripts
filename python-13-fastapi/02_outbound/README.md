# 02_outbound — 外向き通信の作法

**この章の問い**: 呼び出し先が遅いとき、自分も道連れになる構造をどう断つか。

| ファイル | 学ぶこと |
|---|---|
| `shared_client/` | クライアントの生成場所、コネクションプールの上限 |
| `timeout_layers/` | connect/read/write/pool の4分類、階層の逆転チェック |
| `retry_backoff/` | リトライ対象の選別、指数バックオフ＋ジッタ、リトライ予算 |
| `circuit_breaker/` | Closed / Open / Half-Open の3状態 |
| `idempotency_key/` | 非冪等処理を安全にリトライする |

## この章とネットワーク編の対応

| ここで直すこと | ネットワーク編の項目 |
|---|---|
| クライアントを使い回す | 1章 エフェメラルポート枯渇 / SNATポート枯渇 / コネクションプール / Keep-Alive |
| タイムアウトの階層 | 5章 タイムアウトの階層設計、3章 504 |
| バックオフとジッタ | 5章 リトライとサーキットブレーカ、リトライストーム |
| 冪等キー | 3章 冪等性とリトライ |

概念として学んだものが、コードでどう現れるかを確認するのがこの章の目的です。

## 合格基準

- [ ] 既存サンプルの `async with httpx.AsyncClient()` の問題点を3つ以上説明できる
- [ ] `timeout_layers.py` の表を担当システムの実値で埋め、逆転がないか確認した
- [ ] リトライすべき条件と、してはいけない条件を列挙できる
- [ ] 3層が各3回リトライしたときの総リクエスト数を計算できる
- [ ] 「タイムアウトしたが実は成功していた」ケースの危険性を具体例で説明できる
